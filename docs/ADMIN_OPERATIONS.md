# Admin operations integration

Admin operational mutations are protected by the `Admin` role and write an `ActivityEvent` for audit visibility.

## Protected routes

- `POST /api/v1/admin/users/{id}/status`
- `POST /api/v1/admin/communities/{id}/status`
- `POST /api/v1/admin/placements/{id}/status`
- `POST /api/v1/admin/notes`
- `DELETE /api/v1/admin/notes/{id}`
- `GET /api/v1/admin/notes`
- `GET /api/v1/admin/payouts`
- `POST /api/v1/admin/payouts/{id}/status`
- `GET /api/v1/admin/reviews`
- `POST /api/v1/admin/reviews/{id}/resolve`
- `GET /api/v1/admin/reports`
- `GET /api/v1/admin/health`
- `GET /api/v1/communities/verification-evidence/{communityId}/url`

Admin list routes use the shared `PageRequest` contract (`page`, `pageSize`) and return `PageResult<T>` with total counts. The frontend uses UUID mappings when available and retains LocalStorage records only as a staged migration fallback.

Verification evidence URLs are private, short-lived (10 minutes), and generated by the configured object-storage adapter. The Admin UI reports unavailable or expired evidence instead of exposing permanent storage URLs.

Important mutations create audit activity records including the actor, entity, action, and timestamp. Financial records and click history are not deleted by Admin operational actions.
